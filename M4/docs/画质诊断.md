# 画质诊断与创作模式调整

## 用户反馈与问题

当前 AdaIN 结果有细节平滑、局部涂抹和类似模糊滤镜的观感。功能测试、融合一致性与缓存正确性不能证明视觉质量好，不能以测试通过来否定这项反馈。

初版内容与风格尺寸都约为 256，解码得到的 256×256 图像在明信片上被放大到约 620×620，进一步暴露了细节损失。上游测试入口的默认 content_size/style_size 参数为 512；其短边缩放策略与本项目长边/中心裁剪约定不同，不能把两条 CLI 的默认运行直接称为同条件对照。

## 实际完成的诊断

`src/tools/diagnose_quality.py` 使用保留的、未经修改的上游 net.py/function.py，严格加载同一权重，在同一组预处理张量上执行原始网络和 AdaIN。山地试运行图与梵高参考、alpha=0.6 的输出最大绝对误差为 **0.0**。这支持该样例的移植与上游一致，不证明所有输入都好看。

在山地和城市两张试运行内容上生成如下对照，未使用正式评价内容、锐化或模拟输出：

| 内容尺寸 | 风格长边 | 强度 |
|---:|---:|---:|
| 256 | 256 | 0.6 |
| 512 | 256 | 0.6 |
| 512 | 512 | 0.6 |
| 512 | 512 | 0.8 |
| 512 | 512 | 1.0 |

图片：`outputs/runs/quality_diagnosis/resolution_strength_comparison.jpg`；实际原尺寸 PNG 和参数记录位于同目录。所有列按相同显示尺寸展示，512 列是实际推理生成的 512 图，不是将 256 输出插值后冒充高分辨率。

目测这两个样例，512 结果保留了更多建筑、岩石与植被细节；但水面仍有平滑、块状纹理和局部结构变化。提高强度使风格更明显，同时可能加重细节扭曲。这里只做有限样例的视觉观察，没有给出全体图片的质量提升或统计显著性结论。

## 已做的应用调整

- 默认进入独立的“清晰创作 · 512×512”，风格长边 512，初始 alpha 0.8。
- 提供 0–1 的全局强度调节。强度变化只使渲染结果失效，保留同图对编码特征；点击生成时仅重新解码。
- 显示内容与生成结果的并排对照，另提供原尺寸风格化 PNG 下载，便于区分生成损失与明信片显示缩放。
- 正式“实验基线 · 256×256”仍为 alpha 0.6，使用原配置和原性能口径；正式区域搜索入口保留在这一模式。
- 新增 AppTest 检查 512 实际尺寸、强度变化不增加编码调用、切回 256 后清除旧缓存。

## 结论与后续边界

当前没有发现这个样例中的移植数值错误；低分辨率与解码器重建是模糊感的重要可疑因素。AdaIN 匹配通道统计，不保证逐区域重建参考画作的笔触布局或重新绘制语义对象。512 与强度调节改善了可控性，但没有从根本上消除底座局限。

不能靠添加锐化指标、换展示图片或把原图混回 RGB 来宣称方法更好。若用户希望更明显的绘画重构，需要重新评估底座、结构保持和实验公平性，届时应同步 M5/M6 的接口与方法描述。当前未擅自更换生成网络或加入扩散模型。
