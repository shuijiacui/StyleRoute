## 1. 先让代码在自己的电脑跑起来

以下命令从 **StyleRoute 仓库根目录**开始，使用 Python 3.12、Node.js 20+。首次准备需要网络；推理时不下载。

```powershell
cd M4
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r resources/env/requirements-dev.txt
node src/tools/download_assets.mjs
.\.venv\Scripts\python.exe -m src.tools.build_webfonts
node src/tools/download_images.mjs --restore
.\.venv\Scripts\python.exe -m src.tools.prepare_data
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m streamlit run app.py
```

终端保持开启，在浏览器打开 `http://127.0.0.1:8501`。选图→生成风景→制作明信片→弹框内编辑、预览与下载。PowerShell 不需要激活虚拟环境，也不必修改机器级执行策略。macOS/Linux 对应解释器为 `.venv/bin/python`。

Git 提交包括源码、配置、数据清单、原始来源元数据、许可、测试和文档；权重、原图、完整字体、生成字体、虚拟环境与运行输出均通过显式准备命令恢复/生成。权重约94MB，完整字体约47MB，25张源图约7.55MiB。文件 SHA256 不匹配时停止并调查，不能为了继续运行删除核验。

## 2. 三个人用同一套 Python 类型和启动目录

**当前可执行代码使用 `src.*` 导入，工作目录固定为 `StyleRoute/M4`。** 所有 `resources/...` 与 `outputs/...` 配置路径相对 M4；不要再额外加一层 `M4/`。这与旧 README 中尚未实现的 `M4.models.*` 及根目录 `contracts.py` 计划不同。

要从 M4 导入同级 M5/M6，在当前终端增加仓库根目录：

```powershell
# 当前目录：StyleRoute/M4
$env:PYTHONPATH = (Resolve-Path ..).Path
.\.venv\Scripts\python.exe -m src.tools.check_handoff --m5-only
# M6 完成后：
.\.venv\Scripts\python.exe -m src.tools.check_handoff
```

以上设置只作用于本终端。M5/M6 在适配器里统一 `from src.contracts import RegionPack, SearchResult`，不要复制数据类，不要混入 `M4.src.contracts` 或另一份根目录合同，否则 `isinstance` 可能失败。M5/M6 各自包请添加 `__init__.py`，依赖也安装进执行联调的同一个环境。M5/M6 配置文件用其模块 `__file__` 定位，不依赖当前目录恰好是自己的目录。

`resources/configs/team.json` 已准备好同级包入口：

```json
{
  "region_adapter": "M5.regions.adapter:build_regions",
  "search_adapter": "M6.search.adapter:solve"
}
```

这份配置是基线配置，尚未存在的适配器不会被测试替身自动替换。命令默认读取 team.json；页面基线读取 default.json。真实联调通过后，将上述两个入口以及确定的 `search_config` 写入 `resources/configs/default.json`，以同一个设置了 PYTHONPATH 的终端启动页面，选择“实验基线”。当前创作模式不运行区域搜索。

## 3. 与旧计划的差异，必须一起同步

| 项目 | 当前实际情况 |
|---|---|
| 数据来源 | Wikimedia Commons 人工整理照片 + The Met 开放图像；**不是 Places365** |
| 内容数量 | 21张，3张 pilot、18张 evaluation，每类7张；每类01仅供试运行 |
| 风格与图对 | 4张共享风格，12个试运行图对、72个正式图对；正式效果实验尚未执行 |
| 正式基线 | 内容256×256，风格长边256，初始0.6，区域档位0.3/0.6/0.9 |
| 创作界面 | 实际512×512、初始0.8；与正式基线的速度/质量分别记录 |
| 输入范围 | RGB FP32 [0,1]；M4生成编码器不采用ImageNet均值方差 |
| 评价风格图 | `pair.style_rgb` 已提供，M6独立评价器可从这里准备风格Gram |
| SearchResult | 实际字段为 `region_alphas`、`metrics`；旧草案的best_alphas等需适配 |
| 导出 | 三种1500×1000信笺版式；原模型生成像素不会因放大而增加 |
| 已测设备 | Windows/Python3.12、CPU FP32；未提供GPU速度或质量提升结论 |

数据划分、来源与署名详见 [图片集说明](../resources/images/README.md) 和 [manifest](../resources/images/manifest.json)。正式开始前，M6应冻结整个实验配置并确认这份数据方案；不能套用旧版“18个正式图对”的表格。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| `No module named src` | 切到 `StyleRoute/M4`，使用该目录的Python启动 |
| `No module named M5/M6` | 设置上面的PYTHONPATH，检查包名及`__init__.py` |
| 返回类型被拒绝 | 统一导入`src.contracts`，不要复制类或混用`M4.src` |
| 搜索按钮灰色 | 当前为创作模式，或真实适配器/依赖尚不可导入；展开实验信息查看原因 |
| 缺字体/WOFF | 执行字体下载和`src.tools.build_webfonts`，不要只安装字体到Windows |
| 缺权重/图片 | 执行显式资源恢复命令，之后再次核验SHA256 |
| pytest临时目录WinError5 | 本项目已使用`outputs/test-temp/run-随机ID`；不要指定他人拥有的`--basetemp` |
| 与旧图风格效果不一致 | 核对256/512、alpha、风格图片及配置指纹；先固定基线再比较 |
