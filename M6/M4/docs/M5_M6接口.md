# M4 与 M5/M6 的实际接口

GitHub三人协作入口见[交接总览](交接总览.md)、[M5交接](给M5的交接文档.md)和[M6交接](给M6的交接文档.md)。本页描述底层函数合同；同级M5/M6包使用`resources/configs/team.json`，当前本地默认配置的`src.regions/src.search`仍只是可替换入口。

所有路径相对项目根目录解析。配置 `resources/configs/default.json` 的 `region_adapter`、`search_adapter` 指向真实函数；不需要修改 app.py 或复制算法进去。

## M5 提供

默认模块位置为 `src/regions/adapter.py`（建议添加 `src/regions/__init__.py`），函数签名：

```python
def build_regions(content_rgb, *, feature_hw, device):
    # 返回 contracts.RegionPack；函数内部由 M5 实现 SLIC、合并、关系和掩码。
    ...
```

| 字段 | 要求 |
|---|---|
| `content_rgb` | M4 已处理的 PIL RGB；默认 256×256，不是未裁剪原图 |
| `feature_hw` | 真正编码结果的 `(Hf,Wf)`，默认 `(32,32)` |
| `region_ids` | `(0,1,...,N-1)`，顺序固定 |
| `labels` | 整数 NumPy `[H,W]`，恰好包含这些区域 ID |
| `soft_masks` | torch FP32 `[N,Hf,Wf]`，位于指定 device，有限、非负、逐位置和为 1，容差 `1e-5` |
| `edges` | `(source_id,target_id,nonnegative_weight)` 的元组，ID 与区域顺序一致，无自环 |
| `metadata` | M5 的版本、参数和构造信息 |

消失区域、空覆盖、错误尺寸由 M5 修正，不由 M4 静默归一化。M4 `prepare_regions` 校验并复制掩码一次，搜索期间复用该快照。

## M6 提供

默认模块位置为 `src/search/adapter.py`，函数签名：

```python
def solve(*, generate, pair, regions, initial_result, search_config,
          progress_callback=None):
    # 返回 contracts.SearchResult；评分、约束、预算和接受策略均由 M6 实现。
    ...
```

- `generate(tuple_of_alphas)` 返回 `GenerationResult`，不重新编码；正式域为 `0.3/0.6/0.9`，长度等于区域数。
- `initial_result` 已经是全局 0.6 图；默认状态纳入候选预算一次，不再次请求生成同一默认状态。
- `pair.content_tensor` 是内容输入，`GenerationResult.image_rgb` 是规范评分输入，均为 `[1,3,H,W]`、FP32、同设备。不要先转 JPEG、再次裁剪或加滤镜。
- `pair.style_rgb` 是已经按配置缩放的PIL RGB风格参考。M6可调用`image_tensor(pair.style_rgb)`构造自己的评价输入，再执行独立评价器的归一化。
- `pair`、掩码和返回图像按只读约定使用；`frozen=True` 不阻止原地张量修改。评价网络需要 ImageNet 标准化时，由 M6 在自己的评价分支执行；不能修改生成输入。
- 每次 `solve` 使用独立的已评价状态缓存；不同方法不得共享历史候选结果来缩短预算。
- 可通过 `progress_callback(event)` 报告真实阶段或已评价次数；没有总预算时不伪造精确进度。

`SearchResult` 必含：

| 字段 | 含义 |
|---|---|
| `best_image_rgb` | 实际选中的规范图像张量，与 `region_alphas` 对应 |
| `region_alphas` | 最终区域强度元组 |
| `status` | improved / no_improvement / no_feasible / budget_exhausted / cancelled / failed |
| `metrics` | Q/T/S/J；未测值用 None，不能填假零。improved 必须有实测四项 |
| `trajectory` | 可 JSON 序列化的真实轨迹记录 |
| `candidate_count` | 已评价状态数，默认初始状态计一次，至少为 1 |
| `decoder_calls` | 本次方法使用的解码次数，说明是否含提供的默认结果 |
| `state_cache_hits` | 已评价状态缓存命中次数 |
| `metadata` | 必含布尔 `used_default`，以及原因、版本、预算和约束信息 |

默认回退必须用全 0.6、同一默认图，不标记 improved。M4 检查返回类型、尺寸、精度、范围、域、状态及日志字段；图像质量、可行性与“改善”的判断仍由 M6 的真实评分负责。

## 联调顺序

1. M5 单独核对处理后图像、labels、区域顺序、覆盖与 feature_hw。
2. 使用 M4 接口验证全 0.6 与全局一致、同步置换一致、候选之间不污染缓存。
3. M6 先传入现有默认结果，再通过 generate 评估候选。
4. 接入 app.py 的真实搜索入口，检查成功、无改善、失败与预算耗尽状态。
5. 调用 `bench.profile --integrated`，保留完整搜索日志；评分网络单阶段计时由 M6 提供。

当前仓库没有生产版 M5/M6。`tests/` 中的测试替身只验证合同与调用，不构成真实方法实验。
