## 2. M4 给你的内容

| 对象 | 用途与约定 |
|---|---|
| `pair.content_rgb` | 已统一预处理的PIL RGB内容图，与输出坐标一致 |
| `pair.style_rgb` | 已保持比例缩放的PIL RGB风格参考，供独立评价器准备Gram；不是原始未处理大图 |
| `pair.content_tensor` | `[1,3,H,W]` FP32 [0,1]，同生成设备 |

| `initial_result` | 已存在的全局0.6结果，不要再次请求生成全0.6 |
| `generate(alphas)` | 返回`GenerationResult`；只做验证、特征融合、解码，不重新读文件/编码 |

## 3. 候选预算与缓存必须分开

正式区域状态每项属于`{0.3,0.6,0.9}`，长度等于N。M4集成回调拒绝域外状态；底层`engine.render_regions`允许[0,1]仅供其他研究/调试，不能利用这个差异悄悄扩展正式搜索域。

首次评价直接使用 `initial_result.image_rgb`；把全0.6状态和测得分数放入M6状态缓存，并计入一次不同状态预算。命中已评价状态时直接复用图与分数，不能调用generate再假称缓存命中。每个方法/图对的缓存独立，不能从前一种方法免费取得候选。

推荐日志口径：

- `candidate_count`：本次真正评价的不同状态数，含默认1次；重复状态不再增加。
- `decoder_calls`：默认结果生成1次 + 本次generate实际调用次数。若采用别的口径，必须在metadata写清，不与其他方法混用。
- `state_cache_hits`：M6命中已评价状态的次数，区别于M4编码特征缓存。
- `metadata["decoder_count_includes_initial"] = True`：建议显式标明上述默认口径。

M4的engine计数会跨页面会话或先前操作累计，不能直接把全局总计当某次方法成本；需要前后差值。`check_handoff`也包含数值探针解码，报告里的`search_decoder_calls_observed`只记录真正进入solve后的新增解码。

## 4. 返回的 SearchResult

定义和校验分别见 [contracts](../src/contracts.py) 与 [integration](../src/integration.py)。

| 字段 | 要求 |
|---|---|
| `best_image_rgb` | 实际选中候选的RGB FP32 `[1,3,H,W]`张量，同设备、有限、[0,1]；与强度对应 |
| `region_alphas` | `tuple[float,...]`，不是旧草案的best_alphas |
| `status` | `improved/no_improvement/no_feasible/budget_exhausted/cancelled/failed`之一 |
| `metrics` | 至少含Q/T/S/J，真实Python有限数；未测为None，不填虚构的0 |
| `trajectory` | `tuple[dict,...]`，真实且JSON可序列化的轨迹 |
| `candidate_count` | Python int≥1，包含默认；不是numpy.int64或bool |
| `decoder_calls/state_cache_hits` | Python非负int，写明计数边界 |
| `metadata` | 必有布尔`used_default`；补stop_reason、feasible、violation、预算、种子、方法与评分版本等 |

真实评价后“没有改善”的返回示例（以下变量必须来自实际评价与计数）：

```python
return SearchResult(
    best_image_rgb=initial_result.image_rgb,
    region_alphas=(0.6,) * len(regions.region_ids),
    status="no_improvement",
    metrics={"Q": float(q0), "T": float(t0), "S": float(s0), "J": float(j0)},
    trajectory=tuple(records),
    candidate_count=int(unique_evaluations),
    decoder_calls=int(1 + generate_calls),
    state_cache_hits=int(cache_hits),
    metadata={
        "used_default": True,
        "feasible": True,
        "violation": 0.0,
        "stop_reason": stop_reason,
        "decoder_count_includes_initial": True,
        "method": method_name,
        "seed": seed,
        "budget": budget,
    },
)
```

`no_improvement/no_feasible/failed`必须回退到**同一份默认图**、全0.6且used_default=True。`improved`必须used_default=False并有真实Q/T/S/J。预算耗尽或取消可以返回已发现的最佳可行候选，也可以回退默认，均记录真实stop_reason与used_default。没有完成初始化评分而直接抛错时，让异常传播，不伪造“已评价1个状态”。

M4核对形状、数值域、状态、计数和默认回退一致性；M4不会重跑你的评价网络来证明质量改善或可行性。你必须保证选中图与强度/分数来自同一状态，并保留生成结果避免为展示重新解码。

## 5. M6 应落实的算法和公平比较

沿用你原职责说明中的目标，并在独立pilot上冻结具体参数：Q为内容结构代理，T为风格Gram损失，S为边权归一化的强度差平方，J为Q相对默认值的归一化项加λS；风格约束相对同一默认T0定义。评价网络与M4生成编码器独立封装。

需要交付真实目标、可行性/比较器、区域风险、普通/风险局部搜索、随机状态与全局扫描、状态缓存、预算截断、有限重启、默认保底及取消/失败状态。风险贡献应与Q/S总量对应；候选必须重新评价全图，不能假设区域互不影响。

各方法固定同一图对、生成器、分区、目标与预算口径。区域表示对照保持搜索器相同；加权/等权/无协调使用同一分区。不同表示或不同λ下的J含义不同，跨组比较共同Q/T、轮廓指标与成本，不只比较各自J。图、候选数、失败、无改善与提前终止都要保留。

M4当前没有实现这些算法，也没有完成72图对正式评价；不能把UI截图、测试假评分或全局风格化样例写成搜索提升证据。
